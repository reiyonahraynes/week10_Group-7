Week 10 Group Programming Challenge Four-Format Data Recovery and Validation¶

Group 7 Final report

One country dataset with life expectancy, population and GDP per capita was supplied in the DSA4153_Week10_Group_Task_Inputs.zip as CSV, Excel, JSON, and Parquet. Each file contains the same data behind different column names, layouts, and faults. The report shows how the program creates a clean dataset from all four, proves that the agree, produces the pandas and NumPy, verify the exports, and refuse to publish anything if a run fails.

Every number below is produced by running the pipeline when this notebook is executed. nothing is typed in by hand.

3. Recovering the data from each format¶

each file is read as a text first, so nothing will be converted at the moment. Then its columns are renamed to the canonical names using manifest. The reader check the file's size and SHA-256 hash before trusting. Each row then goes through the validation rules. Any row that breaks a rule are quarantined with a reason. Rows that repeat an earlier identical row are removed as duplicates. The rest become the cannonical table.

For every file the rows must reconcile: raw = quarantined + duplicates + canonical

6. Export verification¶

The canonical table is written to CSV, JSON, Parquet and Excel. Each file is then read back, forced through the canonical schema again. It will be compared by key with what was written. Four things are checked per format: row count, values, data types and column order.

8. Failure handling¶

A run publishes nothing unless every step and check passes. All results are written to a staging folder first. Only a complete, fully-checked run replaces the output folder, and any failure deletes the staging folder and leaves the output folder. Failures are sorted into twelve categories so the cause can be understood.

def digest(folder):
    return {p.name: hashlib.sha256(p.read_bytes()).hexdigest()
            for p in sorted(folder.rglob("*")) if p.is_file()}

before = digest(OUT)
results = []
for fname in ["conflicting_key.csv", "missing_column.csv", "unsupported.txt", "does_not_exist.csv"]:
    try:
        ProcessingRun("config.json").run_single_file(Path("data") / fname)
        results.append((fname, "SUCCEEDED (unexpected)", ""))
    except ProcessingFailure as f:
        results.append((fname, f.category, f.message[:90]))
demo = pd.DataFrame(results, columns=["Input", "Category", "Message"])
display(demo.style.hide(axis="index"))
print("Output folder unchanged after the four failures:", digest(OUT) == before)

9. Testing and reproducibility¶

The project has 112 automated tests ( python -m unittest discover -s tests -t . ): unit tests for each module, and end-to-end tests with one test per failure category, each confirming that nothing is published. The suite passes on pandas 3.0.6 and pandas 2.2.3. The pipeline is also deterministic. Its running it twice produces byte-identical exports. Changing reporting_year in config.json (or python main.py --year 1997) regenerates the whole analysis.
